All significant changes to this FHIR implementation guide will be documented on this page.   

### Unreleased

Resolution of the comments from the informative ballot 1.0.0-ballot, see [ballot overview](https://github.com/hl7ch/ch-alis-connect/blob/main/ballots/1.0.0-ballot.md).

#### Added
* [#8](https://github.com/hl7ch/ch-alis-connect/issues/8): `Condition.bodySite` is bound (extensible) to the new ValueSet [CH ALIS Laterality (SNOMED CT)](ValueSet-ch-alis-connect-laterality-snomed.html) (Left, Right, Right and left). The new CodeSystem [CH ALIS Laterality](CodeSystem-ch-alis-connect-laterality.html) holds the ALIS values l, r, b, and the ConceptMap [CH ALIS Laterality to SNOMED CT](ConceptMap-ChAlisLateralityToSnomed.html) maps them to SNOMED CT. ValueSet expansions use the SNOMED CT Swiss Extension.

#### Changed
* [#5](https://github.com/hl7ch/ch-alis-connect/issues/5): `ChAlisEncounter.class` is no longer fixed to inpatient (`IMP`), so outpatient visits (TARDOC, outpatient flat rates) are supported. The sender sets `Encounter.class` from its case data, e.g. `AMB` or `IMP`. The examples are outpatient cases and use `AMB`.
* [#6](https://github.com/hl7ch/ch-alis-connect/issues/6): The bindings of SectionCode and ServiceAssignment.OrderSectionCode to SwissMedicalSpecialities are extensible instead of required, because the CodeSystem is a fragment.
* [#7](https://github.com/hl7ch/ch-alis-connect/issues/7): Cardinalities aligned with the logical models: ParamTyp and ParamValue in the ParameterV40 extension 1..1, `ChAlisPatient.identifier[LocalPid]` 0..1 (PatientID), `ChAlisChargeItem.code.coding.system` 0..1 (ServiceType).
* [#9](https://github.com/hl7ch/ch-alis-connect/issues/9): PersonID, ProviderID and ReferrerID are conveyed in `Reference.identifier` (`performer.actor`, `performingOrganization`, `costCenter`) instead of `Reference.display`, and OrderingProviderID in the ServiceAssignment extension as `valueIdentifier`. A GLN uses the system `urn:oid:2.51.1.3`. EnteredBy stays in `enterer.display`, because it can be a name.
* [#10](https://github.com/hl7ch/ch-alis-connect/issues/10): The displays of the ParamTyp codes are short; descriptions and the datatype of ParamValue (e.g. boolean j/n) are in the definitions.
* The ImplementationGuide resource is generated by SUSHI from `sushi-config.yaml`.

#### Fixed
* [#11](https://github.com/hl7ch/ch-alis-connect/issues/11), [#12](https://github.com/hl7ch/ch-alis-connect/issues/12): The Type columns of the Concept Maps show the element types instead of "todo" (IG Publisher 3.0.1).
* Unique titles for the ParamTyp and PersonTyp ValueSets, a resolvable version of the v2-0092 ValueSet bound to `Encounter.hospitalization.reAdmission`, and broken links on the index page.
